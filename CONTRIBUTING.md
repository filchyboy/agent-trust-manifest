# Contributing

ATM is intended to be a narrowly scoped, inspectable standard.

## Principles

- Keep the core manifest small.
- Push optional complexity into extension specs.
- Prefer additive evolution over breaking change.
- Avoid embedding vendor-specific policy logic.
- Every normative addition should include schema updates and examples.

## Pull requests

Each PR should include, where relevant:

- spec changes
- schema changes
- example updates
- release note entry

## Compatibility

Breaking changes to the core schema require a major version bump.
